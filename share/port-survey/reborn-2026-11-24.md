**60b73d9 "Release 1.1.6: release virtual cores during texture transfers".** Code: 6 lines in
`engine/host/rx_backend.c`. The rest is release paperwork (README, BUILDING, CREDITS, SOURCE-MANIFEST.json,

- **What it does.** `rx_nvn_read_texels` and `rx_nvn_write_texels` give up the calling guest thread's virtual core
  (`hos_vcore_away` / `hos_vcore_back`) around the back end's call, as `rx_nvn_invalidate` already did. The back end
  waits there for the GPU (the replay up to the texture's last writer, then a finish), and a worker the frame needs could
  only run on that core meanwhile.
- **Measured.** None. Their patch notes say no regression or gameplay testing was done and no FPS gain was measured.
- **Ours: already have it.** host/rx_backend.c:571-603 does the same for both calls, from Longshot 1780fbe0 and HeyListen
  77bd2f86, with an off switch (HOS_TEXELS_KEEP_CORE=1). Ours is the better-tested version: its comment records the
  ~1 s hold at an area change (SceneLowPriority's WriteTexels) that it removes. ProjectReLink took the same change in
  0.7.9.4 (550bde6), so three ports now agree on it.
- **Randomizer / lift:** neither.
